# xiaohongshu-mcp v1.0.1

**每种系统只下载一个主程序。** 登录、MCP 服务和人工验证恢复现在都在同一个文件中，不再需要额外的登录或恢复程序。

## 1. 更新内容

- 新增主程序 `login`：打开专用扫码窗口，确认登录并保存状态后退出。
- 新增主程序 `recover`：打开人工安全验证；`recover -fresh` 用于重新扫码，确认成功前保留原登录文件。
- 统一登录/恢复实现，继续使用相同的 `COOKIES_PATH`、站点和代理配置；验证未完成或失败时返回失败状态，不当作成功。
- 保留原来的启动方式：直接运行或传入 `-headless`、`-port`、`-token` 即启动服务，也支持显式的 `serve` 子命令。
- 每个平台从 3 个程序缩减到 **1 个**；同步简化中英文 README、Windows、恢复和构建教程。
- 新增命令分派、帮助/版本无副作用、失败返回值及合成验证页面回归测试。

小红书 / RedNote 双站点支持和原有业务工具保持不变；这次是入口整合，不增加账号权限，也不绕过安全验证。旧 `v1.0.0` 下载保留不变。[查看代码变更](https://github.com/liaogx/xiaohongshu-mcp/compare/v1.0.0...v1.0.1)。

## 3. 使用方法

### macOS：扫码一次，然后启动

把下载文件放在自己的运行文件夹，在终端进入该文件夹后执行：

```bash
chmod +x ./xiaohongshu-mcp-darwin-arm64
export COOKIES_PATH="$PWD/cookies.json"
export XHS_SITE=auto

# 同一个文件：打开扫码登录，完成后退出
./xiaohongshu-mcp-darwin-arm64 login

# 同一个文件：启动 MCP 服务，Ctrl+C 停止
./xiaohongshu-mcp-darwin-arm64 -port=127.0.0.1:18060
```

后续已登录时直接启动服务。也可以先启动服务，通过 MCP 的 `get_login_qrcode` 获取二维码。重新打开终端时设置同一个 `COOKIES_PATH`，已有账号不要换成空的登录文件。

### Windows（PowerShell）

在下载文件所在文件夹执行：

```powershell
$env:COOKIES_PATH = Join-Path (Get-Location).Path "cookies.json"
$env:XHS_SITE = "auto"
.\xiaohongshu-mcp-windows-amd64.exe login
.\xiaohongshu-mcp-windows-amd64.exe -port=127.0.0.1:18060
```

### Linux

使用 macOS 同样的步骤，把文件名换成 `xiaohongshu-mcp-linux-amd64`。扫码/人工验证需要图形桌面或自行配置的可交互图形会话；浏览器还需要相应系统库与字体。详见 [Docker 指南](https://github.com/liaogx/xiaohongshu-mcp/blob/v1.0.1/docker/README.md)。

### 遇到验证：仍用同一个文件

先暂停正在执行的任务，使用相同的登录文件、站点和代理配置：

```bash
# macOS 示例；Windows/Linux 只替换文件名
./xiaohongshu-mcp-darwin-arm64 recover

# 需要重新扫码时使用这一条，确认前保留原登录文件
./xiaohongshu-mcp-darwin-arm64 recover -fresh
```

恢复完成后重新检查登录并做一次只读搜索，不自动重发之前结果不确定的操作。`recover -keyword '咖啡'` 可指定只读搜索检查词；子命令必须放在选项前。

### 连接客户端

- 传输类型：**Streamable HTTP**；地址：`http://127.0.0.1:18060/mcp`。
- 健康检查：`http://127.0.0.1:18060/health`；根路径 `/` 返回 404 不代表故障。
- 查看版本：程序后加 `-version`；查看用法：加 `-help` 或 `recover -help`。这些命令不下载浏览器、不读取登录文件、不启动服务。
- 从 `v1.0.0` 升级时，保留原私有运行目录和配置，停止旧服务后再用新主程序启动；MCP 客户端地址无需更改。不要同时运行两个服务争用同一端口或并行修改同一登录文件。

## 4. 注意事项

- 首次运行联网下载并校验浏览器，后续复用缓存；程序本身不包含浏览器。扫码和安全验证始终需要人工处理。
- 一个文件不等于桌面安装包，也不会自动安装后台服务；服务仍需保持运行。
- 默认 `XHS_SITE=auto`，支持小红书与 RedNote，详细配置见[双站点说明](https://github.com/liaogx/xiaohongshu-mcp/blob/v1.0.1/docs/SITES.md)。同一实例仍只管理一份账号会话。
- 保留原端口默认值 `:18060`；以上例子显式绑定本机。不要将未鉴权服务暴露到公网。
- 登录文件、二维码、日志和回执是私有数据，不要放进公开仓库。登录成功不代表平台评论、搜索等限制已解除。
- 可执行文件未做 Apple 开发者签名/公证或 Windows Authenticode 签名；核对下载来源和 SHA256，不要全局关闭系统安全保护。
- 原有清理功能的能力边界不变，见[清理说明](https://github.com/liaogx/xiaohongshu-mcp/blob/v1.0.1/docs/ACCOUNT_CLEANUP.md)。
- 验证范围：离线 Go/Python 测试、隔离合成页面回归和 Mac 命令入口检查。Windows/Linux 完成交叉编译与格式/构建信息校验，未在对应系统进行真实账号测试；本次发行不执行公开互动。

## 6. Assets 与校验

附件包含 **3 个主程序**，以及 `SHA256SUMS`、`BUILD-INFO.json`、`LICENSE`、`NOTICE`、`THIRD_PARTY_NOTICES.txt`。后五项是校验/说明文件，不是需要安装的程序；GitHub 另外提供源码压缩包。

下载程序后计算 SHA256，与 `SHA256SUMS` 中的同名文件对照：

```bash
# macOS
shasum -a 256 ./xiaohongshu-mcp-darwin-arm64
# Linux
sha256sum ./xiaohongshu-mcp-linux-amd64
```

```powershell
# Windows PowerShell
Get-FileHash .\xiaohongshu-mcp-windows-amd64.exe -Algorithm SHA256
```

SHA256 用于文件一致性校验，不代替发布者数字签名。新版不再提供单独的 `xiaohongshu-login` 或 `xiaohongshu-recover` 下载。
