# 小红书与 RedNote 双站点

同一个服务程序兼容 `www.xiaohongshu.com` 与 `www.rednote.com`。手机号注册地区可能影响扫码后的落地站点；**实际页面确认的登录站点**才是后续操作依据，不以手机号、旧 Cookie 是否存在或手机 App 的状态代替网页验证。

## 启动与迁移

默认自动识别，无需修改客户端工具名、参数或 MCP 地址：

```bash
XHS_SITE=auto ./xiaohongshu-mcp -port 127.0.0.1:18060
```

1. 启动服务，调用 `check_login_status`。
2. 已确认登录时，结果显示站点 `xiaohongshu` 或 `rednote`，随后正常调用搜索等工具。
3. 未登录时调用 `get_login_qrcode`，用 App 手动扫码。若页面跳转 RedNote，成功后会把实际站点与 Cookie 一起原子保存。
4. 旧登录文件无需手动转换。对于未记录站点的旧文件，检查器只在存在会话 Cookie 的受支持站点上尝试实际登录检查；确认后补存站点。Cookie 存在本身不算登录成功。
5. 已保存站点后，后续浏览器及服务重启继续使用它，不因另一域名还有旧 Cookie 就静默切换账号。安全验证、限流等错误不会触发跨站绕过。

登录文件继续兼容原来的裸 Cookie 数组和 v2 对象，v2 新增 `site` 字段，原有 `seed` 保留。Cookie 的域名、值及访问令牌不在两个站点之间改写。

需要指定站点时，登录工具、恢复工具和服务均可使用同一环境变量：

```bash
XHS_SITE=rednote go run ./cmd/login
XHS_SITE=rednote go run . -port 127.0.0.1:18060
# 国内站可使用 XHS_SITE=xiaohongshu。
```

`XHS_SITE` 只接受 `auto`、`xiaohongshu`、`rednote`；其他值启动时报错。显式配置优先于保存的站点；希望跟随扫码后的最终站点时使用默认 `auto`。Docker Compose 同样支持该变量。

显式配置与实际扫码落地站点不一致时返回 `LOGIN_SITE_MISMATCH`，不会保存为一个“已登录但导航到另一个站点”的会话。改用 `auto` 或实际站点后再检查。

一个 MCP 实例仍只管理一份当前账号会话。“双站兼容”不是同时操作两个账号。多实例应分别配置 `COOKIES_PATH`、端口及运行状态目录，避免互相覆盖。

## 适配范围

| 模块 | 两站共同处理 | 路由差异 |
| --- | --- | --- |
| 登录、扫码、人工恢复 | 检查非游客账号，保存实际落地站点；安全验证仍需人工完成 | 国内首页 `/explore`，RedNote 首页 `/` |
| 搜索、筛选、推荐 | 校验结果及筛选状态，只选择可见控件 | 当前站点的 `/search_result` 与首页 |
| 详情、评论、回复、赞、收藏 | 同站点的 ID 与 `xsec_token`，保留业务成功核验及重复发送保护 | 国内 `/explore/ID`，RedNote `/discovery/item/ID` |
| 公开主页、自己的笔记/收藏/点赞 | 等待对应标签数据，不把加载中的空列表当作结果 | 当前站点 `/user/profile/ID` |
| 通知、通知回复和点赞 | 使用当前站点通知页；条目及权限由平台决定 | 当前站点 `/notification` |
| 图文和视频发布 | 使用对应创作平台；非公开发布前确认可见范围 | `creator.xiaohongshu.com` / `creator.rednote.com` |
| 现有清理功能 | 保留账号、所有权、单条确认及私有回执检查 | 对应站点的主页、通知、详情和笔记管理 |
| 图片下载脚本 | `--site auto` 读取 MCP 登录站点，设置对应图片来源 | 见 [DOWNLOAD_IMAGES.md](DOWNLOAD_IMAGES.md) |

搜索或详情的访问令牌应来自当前站点的实际结果，不应复用另一站点、另一账号或过期结果的令牌。

## 验证与边界

```bash
go test ./...
go test -tags browser ./...
python3 -m unittest discover -s scripts -p '*_test.py'
```

默认测试不操作真实账号；`browser` 测试使用隔离合成页面，涵盖两站 URL、编码、旧登录文件迁移、跨站扫码落地保存、隐藏筛选项、列表加载时序、互动回执与清理检查。

真实账号验证先检查登录，再检查搜索、详情、主页和通知；发布及删除只针对明确授权的测试内容。换域名不等于解除账号权限或平台限制。

双站支持不扩展平台原有能力：完整已发评论历史、全部关注名单、群聊退出、私信清空等限制仍见 [ACCOUNT_CLEANUP.md](ACCOUNT_CLEANUP.md)。通知回复需要可用通知，删除他人评论需要对笔记有管理权限，商品功能需要账号权限；缺少测试条件不能声称已实测。发布、评论等仍可能受平台审核、限流或安全验证影响，不保证永久可用或百分之百成功。

“已登录”只确认当前站点能识别账号，不保证所有接口没有额外验证，也不能据此推断登录固定一天过期。安全验证与重新扫码见 [RECOVERY.md](RECOVERY.md)。
