# 评论与点赞结果确认

评论流程按目标笔记就绪、激活编辑器、输入并核对草稿、提交、确认五个阶段执行。各阶段有独立超时；不要求视频、图片等整页内容停止变化。编辑器未展开时可以重新激活编辑器，但不会重复点击发送。

## 如何判断结果

| 返回状态 | 含义 | 后续处理 |
| --- | --- | --- |
| 评论发表成功 | 正常网页提交请求的业务响应明确成功；如平台返回评论 ID，会一并提供 | 可以执行另行授权的点赞 |
| `INTERACTION_NOT_SENT` | 输入、按钮或页面检查失败，尚未点击发送 | 修复具体阶段后再试；若同时包含去重提示，先核验历史记录 |
| `INTERACTION_REJECTED` | 平台明确拒绝提交，返回业务错误码 | 处理原因，不连续重发 |
| `INTERACTION_UNKNOWN` | 可能已经发送，但无法可靠确认 | 不重发、不自动点赞，先核验 |
| `DUPLICATE_OR_UNCERTAIN_COMMENT` | 相同账号、笔记、评论已有提交记录 | 跳过；核验原操作，而不是改字绕过去重 |

HTTP 200、输入框清空、页面短时间内未出现文字，都不能单独证明成功或失败。安全验证仍交由用户手动完成，见 [恢复说明](RECOVERY.md)。

## 减少重复开页

评论明确成功后，服务最多保留当前页面 90 秒。紧接着对同一笔记调用 `like_feed` 时复用此页，确认后关闭；账号会话文件变化或笔记不同则不复用。点赞只点击一次，读取关联的业务响应；初始页面状态没有刷新时，不再次点击以免取消刚完成的点赞。

## 重试保护

提交前会原子写入一条待确认记录，收到业务响应后更新；进程退出或超时也不会自动把待确认状态变为未发送。默认记录目录在 cookies 文件同级的 `state/interaction-receipts`，可用 `XHS_INTERACTION_STATE_DIR` 指定独立目录。键按账号、笔记及评论内容摘要生成，不存 Cookie 或评论正文。请保留该目录，以便重启后继续阻止同一评论重复提交。

这不代替运营流程自己的跨内容去重：以前评论过、点过赞或结果待确认的笔记，仍应在选帖时根据历史记录跳过。本次新增记录无法还原旧版本未记录的操作。

## 不发送的实际页面诊断

```bash
go run ./cmd/check-comment -rounds 3 < /path/to/private-candidates.json
```

输入为 JSON 数组，每项包含 `feed_id`、`xsec_token`、`content`。命令使用服务相同的 `COOKIES_PATH`、`XHS_PROXY` 配置，后台打开页面并填写草稿、检查发送按钮，**永远不提交评论**；遇到登录或安全验证即停止。输出只包含检查轮数、耗时、就绪状态和失败阶段，不打印令牌或草稿。可选 `-diagnostics-dir` 保存失败截图，截图可能含账号及草稿信息，请使用私有目录。
